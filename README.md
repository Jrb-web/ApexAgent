# ApexAgent
ApexAgent（穹枢智控） 一套运行在Windows端的自主推理AI智能体。 实现Thinking/Action分离结构化输出，Agent闭环多轮迭代推理，自研类XML指令协议，支持屏幕视觉识别操控、Windows系统底层API调用，内置三级权限安全隔离。 不再是简单对话机器人，可感知电脑环境、执行操作、根据执行结果继续自主思考完成复杂任务。

PRD
AI桌面Agent系统 开发版PRD（自用正式完整版）

一、项目基础信息

1.1 项目介绍

本项目是基于Python开发的Windows本地AI桌面助手，依托大模型+多模态模型，实现自然语言控制电脑、屏幕视觉操控、系统自动化操作。
项目核心目的：让AI通过语义理解、屏幕视觉感知、环境感知，自主完成Windows各类操作。

1.2 运行环境

系统：Windows10、Windows11
开发语言：Python3.11
协议：MIT开源

1.3 整体架构

前端交互 + Python后端解析引擎 + 大模型API + 多模态视觉API + Windows系统执行API

二、核心架构设计（解决历史所有开发坑点）

2.1 新旧架构对比（本人实际踩坑总结）

旧架构（废弃）

模型输出：人话+指令混合文本
处理方式：后端/前端正则过滤截取
存在严重问题：

1. 模型换行、乱格式导致XML指令裸露在前端，UI极差

2. 指令混杂，正则解析极易失效

3. 执行完指令无反馈，AI单次执行直接结束，无法继续推理

新架构（最终定型、正式开发架构）

采用 ** thinking / action 双字段JSON分离架构 **

1. thinking：纯自然语言，只给前端展示，无任何指令

2. action：纯类XML指令，仅后端解析执行，永远不暴露前端

彻底解决：指令泄露、解析失败、UI乱码所有问题。

2.2 Agent闭环多轮调用机制（核心修复最大开发坑）

历史重大BUG（之前开发卡死的核心问题）

单次对话流程：用户提问→AI生成指令→后端执行→直接结束
致命缺陷：
执行结果不会回传给大模型，AI不知道执行成功/失败、没有获取到查询数据，无法继续完成复杂任务，只能单次傻瓜式执行。

最终正确闭环流程（正式开发标准）

1. 用户输入内容，存入对话上下文

2. 调用大模型，输出标准JSON（thinking + action）

3. 前端只展示thinking

4. 后端解析action内XML指令，校验权限、执行操作

5. 把执行结果/查询数据/错误信息，重新写入对话上下文（同一会话，不新建对话）

6. 后台自动再次调用大模型

7. 模型根据上一步执行结果继续思考、生成新指令

8. 循环往复，直到action为空，任务结束

防护规则（必须开发实现）

• 设置最大迭代轮次（8轮），防止无限死循环

• 工具返回数据只给模型看，不直接抛前端

三、指令解析系统规范

3.1 解析方案（放弃正则，彻底修复多行嵌套解析BUG）

不再使用正则匹配XML指令
正式方案：

1. 后端获取action完整字符串

2. 外层包裹虚拟根节点 <root>

3. 使用标准XML解析库解析

4. 自动兼容：换行、缩进、嵌套标签、If/For多层结构

3.2 异常处理

• XML格式错误、残缺标签：直接拦截、不执行、返回错误至上下文

• 非法API指令：直接丢弃

四、完整自研类XML指令API列表（最终全部可用）

4.1 文件操作API

• <RemoveFile 路径> 删除文件/文件夹

• <DiffJsonFile 路径 替换值> 修改JSON文件

• <SearchFile 文件夹名> 全局搜索文件

• <ReadFile 路径> 读取文件内容

• <ReadFolder 路径> 读取文件夹列表

• <NameChange 路径> 文件重命名

4.2 程序进程控制API

• <OpenExe 程序路径> 打开软件

• <ReadRunning> 获取运行进程

• <KillProcess pid=""> 结束指定进程

4.3 系统基础API

• <Shutdown> 关机

4.4 循环与逻辑API

• <while API名称 次数> 循环执行

• <for(次数,数组) API名称> 批量遍历执行

• <If condition=""> 条件判断分支执行

4.5 环境感知API

• <GetDesktopFiles/> 读取桌面全部文件信息

• <GetActiveWindow/> 获取当前激活窗口

• <GetDiskUsage 路径> 获取磁盘占用

• <GetSystemInfo/> 获取电脑硬件系统信息

• <GetProcessList/> 获取全部进程详情

• <GetNetworkStatus/> 获取网络信息

4.6 窗口精细化控制API

• <CloseWindow 窗口标题> 关闭窗口

• <ResizeWindow 标题 宽 高> 调整窗口大小

• <FocusWindow 标题> 置顶激活窗口

4.7 剪贴板API

• <ClipboardRead/> 读取剪贴板

• <ClipboardWrite 文本> 写入剪贴板

4.8 屏幕视觉操控API（AI看屏幕核心功能）

• <Screenshot 范围 保存路径> 截图

• <MouseMove x y> 相对坐标移鼠标

• <MouseClick x y> 视觉定点点击

• <MouseDrag x1 y1 x2 y2> 鼠标拖拽

4.9 高级系统底层API（权限可控）

• <RegistryRead 路径> 读取注册表

• <RegistryWrite 路径 key value> 写入注册表

• <ServiceControl 服务名 操作> 系统服务控制

• <RunCommand cmd=""> 执行CMD命令

五、三级权限管控体系（开发安全刚需）

Level1 只读权限（默认放行，无需确认）

所有查询类、读取类API，不会修改系统数据

Level2 用户操作权限（默认开启，必须弹窗确认）

文件删除、窗口修改、鼠标点击、文件改写

Level3 系统底层管理员权限（默认关闭）

注册表、进程杀死、服务控制、CMD命令
限制：

1. 需要手动开启总开关

2. 每次执行双重确认

3. 内置高危命令黑名单，自动拦截毁机指令

六、多模态视觉识别实现规范

1. 后端执行截图API保存图片

2. 上传多模态模型

3. 模型识别画面内容，输出0~1归一化相对坐标

4. 后端换算真实屏幕像素坐标

5. 确认弹窗后执行鼠标操作

6. 结果回传Agent闭环

七、系统容错机制（开发必写）

1. 大模型JSON格式错误：直接拦截，提示重试

2. XML指令解析失败：终止执行，报错回传上下文

3. 权限不足：捕获异常，反馈结果

4. 高危操作全部二次确认

5. 模型幻觉非法指令自动拦截

八、完整最终数据流（开发定稿）

用户输入
→ 拼接对话上下文
→ 大模型输出JSON(thinking/action)
→ 前端渲染thinking
→ 后端解析XML指令
→ 权限校验 & 黑名单校验
→ 执行Windows操作
→ 执行结果/数据回填上下文
→ 自动二次调用大模型（闭环迭代）
→ 直至action为空结束任务
→ 输出最终结果
